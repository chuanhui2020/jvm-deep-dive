# G1 / 分代 ZGC：对照与面试追问

本篇提供 24 个专题问题。先用两分钟说主链路，再讨论变体和证据；参考要点用于检查遗漏。既要回答“做了什么”，也要回答“不这么做会怎样出错”。前置为 [G1](G1.md)、[分代 ZGC](GENERATIONAL_ZGC.md)与[日志实验](EXPERIMENTS.md)。

## 1. 机制对照

| 维度 | G1 / JDK 25 | 分代 ZGC / JDK 25 |
| --- | --- | --- |
| 基本组织 | Region，按年轻/老等角色管理 | 分代与 ZPage/年龄等管理 |
| 主要存活信息 | 标记位图、SATB 等 | 标记信息、颜色/屏障与 SATB 等 |
| 典型跨代/跨区记录 | 来源卡及 remembered/card-set 信息，范围不限于 old→young | 主要为年轻收集记录老字段位置，双位图等协调 |
| 常规对象搬迁 | 年轻/mixed 在 STW 中疏散 | 大量重定位与应用并发 |
| 应用读引用 | 常规强引用不采用 ZGC 式通用搬迁修复协议 | load barrier 处理适用的颜色/旧位置修正 |
| 写侧职责 | SATB 旧值与脏来源卡分别处理 | store barrier 配合旧值标记与字段位置登记 |
| 阶段切换 | 并发标记与年轻/mixed 协调 | Young/Old 颜色、根与重定位状态协调 |
| 压力退化线索 | 疏散失败、Full GC、humongous 等 | 分配等待、代周期与回收收益、最终 OOM 等 |

表格描述主要机制，不穷尽特殊引用、JNI、编译代码和其他慢路径。不能用“G1 只有写屏障，ZGC 只有读屏障”作答案。

## 2. G1 的十二个追问

1. **为什么 Region 化还需要分代？** Region 是管理粒度，代是利用对象寿命安排工作的策略；二者并不互斥。继续解释年轻角色与老候选怎样影响 CSet。
2. **RSet 为什么记录引用的位置，而不只记住目标对象？** 搬迁后需要找到并修正入边；位置可由来源卡近似表达，扫描时还需过滤。画一个 CSet 外的对象指向 CSet 内对象。
3. **卡表、RSet、SATB 队列能互换吗？** 分别解释来源块状态、跨范围入边摘要与旧引用标记工作。它们解决的问题不同，容量和处理阶段也不同。
4. **SATB 为什么记录被覆盖的旧值？** 画出标记开始时存在、但扫描前被删除的边，说明如何避免丢失快照所需对象。再解释浮动垃圾为何是保守结果。
5. **并发标记结束是否就释放了所有老垃圾？** 不是；标记提供存活与候选信息，mixed 等路径负责后续空间回收。没有足够价值的候选也可能不按预期产生 mixed。
6. **STW 时为什么复制对象还需要原子转发？** 应用暂停不意味着 GC 工作线程串行；多个 worker 可能同时发现同一个对象。需要一致目的地并处理多余副本。
7. **Mixed 和 Full 有何区别？** Mixed 选择年轻区域加部分老候选做疏散；Full 有全堆处理路径。说明为什么不能只按“涉及老年代”分类。
8. **调小 MaxGCPauseMillis 为什么可能降低吞吐？** 预算影响年轻大小和候选工作量，可能增加回收频率与固定开销；实际影响要由负载和存活率验证。
9. **为什么老年代未满就启动并发标记？** 标记期间仍有晋升和分配，必须给并发工作及后续回收留时间。用增长率×周期时间的简化预算解释，不把它当精确 IHOP 公式。
10. **有空闲 region 为什么 humongous 分配仍失败？** 大对象要求连续区域且含头/对齐；总空闲与连续性、尾部浪费不同。给出 1 MiB payload、1 MiB region 的算例。
11. **Evacuation failure 是否一定说明目的空间耗尽？** 需要区分 allocation 与 pinning 等原因及保留处理；不能看到同一个词就统一调大 Xmx。
12. **JDK 25 是否已经采用 JEP 522 双卡表路径？** 没有，522 的交付版本为 26。25 应从脏卡队列/refinement 的固定标签源码解释。面试中先校准版本，再谈优化收益。

## 3. 分代 ZGC 的十二个追问

13. **颜色在对象头里还是引用里？** 先区分字段槽、编码引用和对象，再解释 ZGC 的引用表示元数据；不要把所有指向同一对象的引用都当作一个同步变化的业务状态。
14. **load-good 与 store-good 有什么区别？** 当前阶段所需处理条件不同。读得到有效地址与写侧标记/remembered 工作满足要求不是同一判断，也不等于 Java 内存模型语义。
15. **为什么分代实现增加写侧职责？** 老→年轻记录和 SATB 旧值处理需要写屏障参与；普通读屏障不应被说成负责一切标记。结合实际入口解释普通与特殊引用访问的差别。
16. **act-once 为什么安全，周期变了怎么办？** 解释相应 epoch 下首次写侧工作、已满足条件的快速检查和阶段颜色切换；不是终生跳过，也不是不处理新旧引用的来源约束。
17. **ZGC 记忆集为什么是字段位图？** 它需要更精确地定位老字段中的年轻入边，current/previous 协调登记与扫描；说明字段目标变为 null/old 后怎样过滤或改变后续登记要求。
18. **读到已移动对象的旧位置会发生什么？** 根据颜色与代/转发信息得到有效目标，必要时参与协调，再返回正确地址；不是直接解引用废弃内存。
19. **自修复为什么使用 CAS？** 防止覆盖应用或其他屏障已完成的字段更新，还要满足元数据转换约束。画出读取旧值、业务写新值、自修复竞争的时间线。
20. **转发表什么时候可以删除？** 需要把来源空间复用、旧引用修正及映射生命周期分开；回答依赖阶段和根协议，不能说对象复制完就立即删全部表。
21. **Major 是否等于先做完一次普通 Minor，再完全独立收 Old？** 不等于。major 年轻路径参与同时建立标记状态及 young→old 入口，old 阶段与后续 young 工作也要协调。
22. **晋升是否总是把每个对象复制进某块固定老年代？** 需要讨论页年龄、目标分配和页角色变化等路径；晋升还可能制造新的 old→young 边，要维护记忆集。
23. **暂停很短为什么仍有 Allocation Stall？** 应用可能等空间；核对分配率、存活集、回收速度、CPU 配额和容量余量。它不能直接等同 G1 的一次 Full GC。
24. **为什么不照搬传统 Survivor 和 G1 参数调 ZGC？** 布局、阶段与调度模型不同。先使用本版本支持的参数，区分软堆目标、硬预算和实际负载，再验证收益。

## 4. 三个综合白板题

### A：G1 Object Copy 下降，但 Scan Heap Roots 上升

先确认同样的日志级别和负载窗口。候选解释包括存活复制量减少、跨区引用来源更多、来源卡密度或积压变化等；把“复制的对象字节”与“寻找入边的工作”分开。用 phases/remset 与分配/引用修改特征补证，不仅根据总暂停判断算法变好或变坏。

### B：ZGC STW 持续很短，业务 P99 却升高

先对齐时间窗口，检查 Allocation Stall、并发 GC 与业务的 CPU 竞争、容器限流及下游排队。若回收后存活集稳定，可研究压力和预算；若长期增长则继续追根路径。不能仅凭几条微秒级暂停排除 JVM 的间接影响。

### C：长寿命缓存不断替换短命值

对同一条引用赋值，分别画出 G1 的 SATB 旧值、来源卡和 remembered 路径，以及 ZGC 的 prev/p、store-good、缓冲与字段位图路径。再引入一次对象搬迁，说明 G1 的暂停内疏散与 ZGC 的并发读侧修正怎样不同。最后说明这些机制都不会替业务决定缓存容量或清理过期数据。
