# 面试追问与诊断案例

这份清单用于检查理解，不是背诵答案。每题先给两分钟主链路，再接受“改变一个条件”的追问。回答必须包含机制、例子、证据和适用边界；涉及实现时明确 **HotSpot / JDK 25**。

## 第 01 章：全景与指标

1. **JVM 规范、HotSpot 与 JDK 分别是什么？** 规范描述合法行为与抽象结构，HotSpot 是实现，JDK 提供运行时和工具。追问：规范的操作数栈为什么不阻止寄存器优化？
2. **Java 为什么既被称为解释执行，又能接近机器码性能？** 说明解释、分层编译、热点画像与机器码执行。追问：首个请求与稳定运行时成本为何不同？
3. **Xmx=2g，进程为什么可能超过 2g？** 说明堆以外的本地结构与 reserved/committed/RSS。追问：容器还需给哪些部分留余量？
4. **JVM 参数看起来一样，结果为什么不同？** JDK 构建、平台、可见 CPU、容器限制和 ergonomics 都可能影响结果。用 L01 说明如何确认目标进程，而非猜测。

## 第 02 章：字节码与调用

5. **局部变量槽与操作数栈如何协作？** 手动执行 L02 的 compute，区分源码变量、逻辑槽和机器帧。追问：long/double 与槽位有什么关系？
6. **invokevirtual、invokeinterface、invokestatic、invokespecial、invokedynamic 区别？** 讲调用语义与链接方式，再举构造器、接口、字符串拼接例子。追问：虚调用为什么可能被内联？
7. **类文件常量池、运行时常量池、字符串池是一回事吗？** 区分文件符号表、运行时表示和 intern 的字符串共享机制；不要都说成同一块内存。追问：字符串拼接结果是否必然 intern？
8. **synchronized 方法为什么没有 monitorenter？** 方法访问标记与同步块指令是不同表达方式。用 L02 的异常表解释同步块异常退出仍需释放锁。

## 第 03 章：类加载

9. **加载、链接、初始化分别做什么？** 说明验证、准备、解析与静态初始化；解析可以延迟，普通静态赋值不是准备阶段执行。追问：编译期常量有何特殊性？
10. **Class.forName 是否一定初始化？** 区分单参数形式和带 initialize=false 的形式，以及 ClassLoader.loadClass。用 L03 解释读取继承来的静态字段。
11. **相同 class 为什么可能转换失败？** 类型身份包含定义加载器；用 L04 举证。追问：发起加载器与定义加载器有何区别？
12. **父委派能否打破，SPI 为什么用 TCCL？** 讲策略、核心类型一致性与可见性边界；再讲父侧框架寻找业务实现。追问：热部署时 TCCL 如何成为保留链？

## 第 04 章：内存与对象

13. **方法区、Metaspace、永久代有什么关系？** 前者是规范概念，后两者是不同年代的实现选择；现代 HotSpot 不存在永久代。追问：静态字段的引用与它引用的对象是否在同一位置？
14. **对象到底占多少字节？** 先问平台、头模式、引用压缩与对齐，再区分浅大小和保留大小。用 L05 解释为何紧凑头不让所有对象等量变小。
15. **TLAB 为什么能加速分配？** 线程在已分配的堆缓冲区中进行本地指针推进，降低共享竞争；仍有边界检查和慢路径。追问：TLAB 是否属于线程栈？
16. **所有对象都一定在堆上吗？** 从可观察语义与优化后的物理表示分别回答；某个对象可能被标量替换而没有实际分配。追问：这能否称作普遍的对象栈上分配？

## 第 05 章：生命周期

17. **循环引用为什么能回收？** 根可达性而非简单引用计数；用 L06 画图。追问：有强引用是否就一定是 GC root？强引用是一条边，root 是遍历起点，二者不同。
18. **弱引用对象为什么还没回收？** 检查真实强引用、GC 是否执行、引用处理及队列通知时序。一次超时不能否定可回收性。
19. **ThreadLocal 弱 key 为什么仍泄漏？** 存活线程→map entry→强 value 的链可能继续存在；remove 和线程生命周期都重要。追问：线程池为何更容易暴露问题？
20. **软引用能做可靠缓存吗，Cleaner 能替代 close 吗？** 回收策略与通知时机都不能提供业务容量和及时释放保证。资源生命周期优先显式管理。

## 第 06 章：GC 共性

21. **分代为什么通常有效？** 对象寿命分布让集中处理年轻对象有收益，但这是假设而非所有负载的定律。追问：长寿命对象很多时会怎样？
22. **只收年轻代，如何知道老对象引用了谁？** 解释写屏障、卡表、记忆集的作用与区别，画 old→young。不能说“年轻 GC 完全不看老年代”。
23. **并发标记为什么需要屏障？** 先构造并发删边/改边的漏标风险，再讲 G1 SATB 保留快照所需信息。追问：为什么浮动垃圾仍可能留下？
24. **GC 暂停、到达 safepoint 的时间、业务 P99 是一回事吗？** 解释不同时间窗口与工作来源；长尾还可能来自排队、I/O 和调度。用日志及时间轴连接，而非直接等同。

## 第 07 章：收集器

25. **G1 一次完整回收周期包含什么？** 区分年轻代回收、并发标记、remark/cleanup 与后续 mixed collection；阶段顺序与触发要结合日志。追问：mixed 是否等于 Full GC？
26. **MaxGCPauseMillis=100 能保证不超过 100 ms 吗？** 是启发式目标，不是 SLA；存活集、复制成本和可用资源影响结果。追问：调小目标可能牺牲什么？
27. **ZGC 为什么低停顿，还需要什么代价？** 讲并发工作、引用屏障与分代结构，再讲 CPU、内存余量和分配等待。JDK 25 不提供非分代模式选择。
28. **什么情况下换收集器？** 从业务 SLO、CPU/内存预算、存活率和分配负载建立比较方案。L08 的短程序只解释机制，不足以做生产选型。

## 第 08 章：编译优化

29. **new 在源码里出现，为什么分配接近零？** 逃逸分析使标量替换和分配消除成为可能；用 L09 的分配计数对照。追问：关闭 EA 后为何变化？
30. **内联有什么价值与限制？** 消除调用开销并扩大优化范围；受代码大小、画像、预算等影响。追问：多个接收者类型与类加载变化如何影响优化？
31. **OSR 和去优化是什么？** OSR 让正在执行的循环切入编译代码；去优化在假设不再成立等情形恢复可正确执行的状态。不能把去优化一律当成 JVM 故障。
32. **怎么避免错误的 Java 微基准？** 考虑预热、独立 fork、死代码消除、常量折叠、结果消费与环境干扰。追问：JDK 25 AOT 缓存为何仍需有代表性的训练？

## 第 09 章：JMM 与锁

33. **volatile 发布如何使普通字段可见？** 画出程序顺序→volatile 同步→程序顺序的 happens-before 传递链。L10 中不应把 sleep 或 println 当作同步手段。
34. **volatile++ 为什么不原子？** 单次读写有语义保证，组合的读改写仍可交错。用 L10 稳定交错与 CAS/锁作对照。
35. **DCL 为什么通常要求 volatile，final 又保证什么？** 前者需要正确发布与排序语义；后者有构造期初始化安全规则，但不保护任意后续修改或 this 逃逸。追问：对象引用可见是否代表其所有可变状态永远安全？
36. **锁语义、锁实现与 CAS 各解决什么问题？** 互斥与同步关系属于语义，具体 monitor 快路径依实现；CAS 是单个比较更新，不自动提供跨字段事务。不要背 JDK 8 偏向锁升级图回答 JDK 25。

## 第 10 章：虚拟线程

37. **virtual、carrier、platform thread 什么关系？** 虚拟线程由 JVM 调度到 carrier 上运行，可在支持的等待点卸载，恢复可换 carrier。追问：为什么 CPU 密集任务不会凭空加速？
38. **synchronized 内 sleep 在 25 还必然 pin 吗？** 否；JEP 491 已处理 monitor 相关情形。用 L11 的唯一 carrier 与全员 barrier 举证，保留本地调用等剩余情况的边界。
39. **为什么升级后共享锁里的吞吐仍没提高？** carrier pinning 与锁的互斥语义不同；同一临界区仍串行。追问：如何区分锁竞争、carrier 受阻与数据库连接等待？
40. **虚拟线程需要池化吗，怎么限制并发？** 通常每任务一个虚拟线程，按稀缺资源限制并发；线程廉价不代表数据库连接或 ThreadLocal 内存无限。追问：上下文传递如何考虑 ScopedValue？

## 第 11 章：内存故障

41. **Java heap space 与 Direct buffer memory 如何区分？** 结合消息、分配路径、显式限制与证据；用 L12 解释为何加堆没解决直接内存限制。
42. **Metaspace 一直涨是不是内存泄漏？** 先看类加载趋势和是否趋稳，再查加载器保留链、类卸载条件及动态生成类。单次增长不能定性。
43. **栈溢出与 unable to create native thread 有何不同？** 前者针对调用深度，后者可能涉及线程/地址空间/系统资源限额；增加 Xss 还可能增加平台线程内存压力。
44. **NMT、heap dump 与 RSS 各能说明什么？** NMT 给 HotSpot 跟踪的本地内存，dump 给堆对象关系，RSS 给进程驻留视角。不能互相替代，也不能用一个数直接推出泄漏原因。

## 第 12 章：诊断与验证

45. **CPU 100% 先做什么？** 确认进程、时间窗、核心口径与线程 CPU，再多次采样/JFR，区分业务、GC、编译或重试。L14 的 burn 是一个有证据的练习。
46. **线程全在 WAITING，就是死锁吗？** 等待是状态，死锁要构造不可推进的等待环。平台线程例子可从 Thread.print 找锁拥有者和等待者；虚拟线程的工具覆盖要单独考虑。
47. **GC 后占用升高就能认定泄漏吗？** 先统一负载与回收阶段，区分预热、缓存、存活集变化，再看持续趋势与根路径；不能把不同 GC 阶段的数直接比较。
48. **调优改动如何证明有效？** 在同构环境、同负载和可比窗口下比较吞吐、P99、CPU、内存和错误率；同时说明代价与回退条件。一次平均耗时下降不足以证明服务更稳定。

## 综合案例

先独立推理，再读下面的参考路径。每题交付一张时间轴、一条可验证的因果链和一个修复后的回归方案。

### 案例 A：发版后 P99 翻倍，GC 暂停没有明显增加

**给定：** 请求量相同，平均延迟变化小，P99 变差。

**参考路径：** 先对齐时间窗、分位数口径和下游指标；观察 CPU、排队、monitor 竞争、编译/去优化与 safepoint。JFR 中找到热点或等待，并用重复采样与代码路径关联。没有 GC 暂停增长只降低某些 GC 假设的优先级，不能排除其他 JVM 或业务等待因素。修复后重放相同负载，比较尾延迟及资源代价。

### 案例 B：堆只用一半，容器却因内存超限重启

**参考路径：** 先确认是否由容器/OS 杀进程；对齐 RSS、堆 committed/used、线程数、直接内存和 NMT。若堆外增长与 buffer 使用相关，结合 buffer pool 指标与业务持有者查证；若线程暴涨，查平台线程资源与创建路径。不要先把 Xmx 调大，使预算更紧张。

### 案例 C：热部署数次后 Metaspace 耗尽

**参考路径：** 比较已加载/卸载类与加载器数量；用堆根路径找旧加载器的存活引用，检查 TCCL、静态缓存、后台线程和 ThreadLocal。修复生命周期后重复部署并验证加载器可释放；增大上限只能延缓问题，不能替代根因处理。

### 案例 D：改成虚拟线程后数据库超时更严重

**参考路径：** 区分运行任务数、连接池容量、排队长度与数据库服务能力。更多等待任务可能放大下游竞争；使用资源导向并发限制、合理超时与取消，再验证等待与吞吐。JDK 25 下不要未经证据就把所有 synchronized 都改成 ReentrantLock。

### 案例 E：CPU 很高、GC 频繁，但每次回收后占用很低

**参考路径：** 初步候选是分配速率高或堆配置太紧，而不是仅凭频繁 GC 判定泄漏。JFR 查分配来源，GC 日志查频率、阶段与存活集；减少无效分配或调整预算后，比较每请求分配、CPU、暂停与吞吐。与 L07 对照，但不要把小实验的参数直接复制到生产。
